# Config Document Preparation Loading Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a branded, layout-preserving document-preparation loading skeleton to PrintBit's `/config` page using native HTML/CSS plus a small local DotLottie animation.

**Architecture:** Keep the real `/config` DOM mounted and style it into a page-level `preparing` state. A focused `ConfigPreparationLoadingController` owns accessibility, interaction locking, status copy, reduced-motion behavior, and optional DotLottie lifecycle, while existing preview/render/analysis logic continues to own document processing.

**Tech Stack:** HTML, CSS, TypeScript, esbuild, `@lottiefiles/dotlottie-web`, Jest where practical.

**Spec:** `docs/superpowers/specs/2026-08-29-config-document-preparation-loading-design.md`

## Global Constraints

- Preserve the existing `/config` layout and control geometry.
- Use local assets only, no CDN or network-hosted animation.
- Full-screen Lottie recreation is prohibited.
- Document preparation must never wait on animation initialization.
- Lottie failure must degrade to CSS-only loading without blocking the workflow.
- Continue and config controls remain non-interactive while preparation is active.
- Back remains usable.
- `prefers-reduced-motion: reduce` disables shimmer and continuous animation.
- Print, copy, and scan flows must all leave preparation state on success or recoverable failure.
- No server API changes.

- [ ] **Step 1: Write the controller module**

Create `src/public/config/loading-state.ts`:

```ts
import { DotLottie, setWasmUrl } from '@lottiefiles/dotlottie-web';

export type ConfigPreparationState = 'preparing' | 'ready' | 'error';

export interface ConfigPreparationLoadingController {
  start(message?: string): void;
  setMessage(message: string, detail?: string): void;
  finish(): void;
  fail(message?: string): void;
  destroy(): void;
}

interface ControllerOptions {
  setContinueEnabled: (enabled: boolean) => void;
}

const DEFAULT_TITLE = 'Preparing document';
const DEFAULT_DETAIL = 'Building your print preview…';

export function createConfigPreparationLoadingController(
  options: ControllerOptions,
): ConfigPreparationLoadingController {
  const layout = document.getElementById('configLayout');
  const preparing = document.getElementById('configPreparing');
  const canvas = document.getElementById(
    'configPreparingAnimation',
  ) as HTMLCanvasElement | null;
  const status = document.getElementById('configPreparingStatus');
  const detail = document.getElementById('configPreparingDetail');
  const paperLoading = document.getElementById('paperLoading');

  const reducedMotion = window.matchMedia(
    '(prefers-reduced-motion: reduce)',
  ).matches;

  let animation: DotLottie | null = null;

  const ensureAnimation = (): void => {
    if (!canvas || reducedMotion || animation) return;

    try {
      setWasmUrl('/vendor/dotlottie/dotlottie-player.wasm');
      animation = new DotLottie({
        canvas,
        src: '/config/assets/document-preparing.lottie',
        autoplay: true,
        loop: true,
      });
    } catch (error) {
      console.warn(
        '[CONFIG PREPARING] DotLottie unavailable, using CSS fallback',
        error,
      );
      preparing?.setAttribute('data-lottie-unavailable', '');
    }
  };

  const setState = (state: ConfigPreparationState): void => {
    layout?.setAttribute('data-preparation-state', state);
    layout?.setAttribute('aria-busy', state === 'preparing' ? 'true' : 'false');
  };

  return {
    start(message = DEFAULT_TITLE): void {
      setState('preparing');
      status && (status.textContent = message);
      detail && (detail.textContent = DEFAULT_DETAIL);
      paperLoading?.classList.remove('hidden');
      options.setContinueEnabled(false);
      ensureAnimation();
    },

    setMessage(message: string, nextDetail = DEFAULT_DETAIL): void {
      status && (status.textContent = message);
      detail && (detail.textContent = nextDetail);
    },

    finish(): void {
      setState('ready');
      paperLoading?.classList.add('hidden');
      animation?.pause();
    },

    fail(message = 'Preview unavailable'): void {
      setState('error');
      status && (status.textContent = message);
      paperLoading?.classList.add('hidden');
      animation?.pause();
    },

    destroy(): void {
      animation?.destroy();
      animation = null;
    },
  };
}
```

If the installed DotLottie version exposes a slightly different WASM configuration API, use the exact API from `@lottiefiles/dotlottie-web@0.79.2`; keep the controller interface unchanged.

# Epson L5290 Assisted Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an authenticated, idempotent admin recovery that clears every live Epson print job, cycles the exact L5290 PnP device, reconciles customer funds, restores Idle only after health verification, and never lets Epson UI cover the kiosk.

**Architecture:** The C# Worker owns the dispatch gate, filesystem queue, Windows spooler, device cycle, health verification, and concise operational logs. Node.js persists the operator intent, gates customer work before charging, calls the Worker through the existing command pipe, reconciles refunds versus `NeedsReview`, and renders the admin workflow. Recovery is a persisted saga across SQLite, Worker journal files, the spooler, and PnP state; retries reuse one recovery ID and never repeat an unknown device cycle.

**Tech Stack:** Node.js 22.5+, TypeScript 6, Express 5, SQLite (`better-sqlite3` through the existing storage layer), Jest 30, C#/.NET 10 Windows Worker Service, `System.Management`, xUnit, Moq, Windows PnP/Win32 printer APIs, PowerShell kiosk provisioning.

**Spec:** `docs/superpowers/specs/2026-09-06-epson-l5290-assisted-recovery-design.md`

## Global Constraints

- Work in isolated worktrees for both `C:\Users\printbit\printbit` and `C:\Users\printbit\printbit-worker`; both current worktrees contain unrelated user changes that must remain untouched.
- Keep `src/public/config` and its existing `copies`, `color`, `pageRange`, `orientation`, and `quality` handoff behavior unchanged.
- Automatic hardware detection may close dispatch, but only an authenticated, persisted, idempotent admin intent may clear queues or cycle PnP hardware.
- Target only the configured `EPSON L5290 Series` device container and its exact enrolled PnP instance IDs. Missing, changed, or ambiguous identity fails closed.
- The printer and scanner may disconnect briefly during the approved device cycle; both must return before Idle.
- Quarantined work is never reprinted automatically.
- Preserve the existing `SemaphoreSlim` serialization and the two-minute print timeout; extend the coordinator rather than removing either protection.
- C# Information logs are limited to one recovery start and one recovery success, with one Warning per fault episode and one Error per failed recovery. Polling and unchanged states are not logged.
- Never log document names, document contents, student data, payment details, complete paths, raw commands, or full PnP identifiers.
- Do not add new npm or NuGet dependencies unless an existing platform API cannot satisfy a reviewed requirement.
- Run `graphify update .` in the Node repository after code changes and include the updated graph artifacts only when generated by that command.
